# Spine Pair Review — language-learner

## Overall verdict
The pair is a usable contract. Every color token has a hex value, every `{token}` reference resolves, all 14 mockups are cited inline, and each in-app PRD journey has a Key Flow with a climax and a failure path. No finding is critical. Three high findings should be fixed before story-dev: Reference audio auto-play contradicts FR-31 and the iOS user-gesture rule; the 2px `border` outline on text fields (1.38:1) fails the stated WCAG 2.2 AA non-text contrast target; and the Pronunciation surface has no cold-load / pre-session Sync state. No spine content contradicts `.memlog.md`. One memlog decision is missing from the spines (see §7).

## 1. Flow coverage — adequate
Checked: PRD §2.3 UJ-1…UJ-6 against EXPERIENCE.md Key Flows. UJ-1→J1, UJ-2→J2, UJ-3→J3, UJ-5→J4, UJ-6→J5. UJ-4 is declared out-of-UI with OQ-5. Each flow names Oleksii, has numbered steps, a **Climax** beat and a Failure line. J1's device deviation from UJ-1 is noted and follows the memlog.
### Findings
- **high** Interaction Primitives says "Reference audio auto-plays before the first Attempt and before each retry (FR-31)". FR-31 only says the user *can play* it. Responsive & Platform says iOS Safari needs a user gesture to start audio playback, and the first Card loads with no gesture. The order of events after "Try again" is also undefined: does the reference play first and then recording start, or does the tap start recording? J3 step 2 ("Reference audio plays; he taps record") inherits the ambiguity. (EXPERIENCE.md Interaction Primitives; Responsive & Platform; J3 step 2). *Fix:* pick one rule. Either an explicit play tap (matches FR-31 and iOS), or auto-play only on a gesture-initiated load (after a Rating tap, after "Try again") with a stated fallback when blocked. Then state the order of "Try again", replay and record.
- **low** J2 departs from PRD UJ-2: Custom value instead of Use as is, no edits instead of trimming an alternative, and no Mnemonic. The memlog sanctions this (J2 decision), but unlike J1 the flow carries no deviation note. As a result, no flow exercises Draft editing (FR-18) or the user-only Mnemonic. (EXPERIENCE.md J2). *Fix:* add a one-line note like J1's, or add a variant step where Oleksii edits a field and adds a Mnemonic.

## 2. Token completeness — adequate
Checked: 33 colors (all hex; `scrim` is 8-digit hex = 42%), 21 typography roles, 12 radii, 26 spacing tokens, 41 component token groups. All 86 distinct `{path}` references in DESIGN.md and both references in EXPERIENCE.md (`{colors.accent}`, `{spacing.target-min}`) resolve. Recomputed every stated contrast ratio and found all accurate (for example accent/white 6.73, on-feedback-fair/feedback-fair 6.40, white/feedback-poor-strong 5.18). Light-only is declared, so no dark pairs are needed.
### Findings
- **high** `border` `#E2DACF` is the only visible boundary of `text-field`, `button-secondary` and `rating-button` on white cards, at 1.38:1 (1.32:1 on `ground`). The Colors table calls this "decorative, the label carries meaning". For text inputs, though, the boundary is what identifies the control, and WCAG 2.2 AA 1.4.11 (the target in Accessibility Floor) requires 3:1. (DESIGN.md Colors `border` row; components `text-field`, `rating-button`). *Fix:* add a stronger outline token (for example ≥3:1 against `surface`) for field borders, or give fields a `surface-sunken` fill. Then state the decision for buttons explicitly: label-identified buttons are exempt, or they also get the stronger outline.
- **low** Several component values bypass the scale as raw literals: `readiness-fix-hint.radius: 16px` (no `rounded` token is 16), `bottom-sheet.radius: '28px 28px 0 0'` (should derive from `{rounded.card-lg}`), `nav-pill.height: 44px` (= `{spacing.target-min}`), and `queue-count-chip` fontSize/weight (13/700 matches no typography role). (DESIGN.md frontmatter `components`). *Fix:* reference existing tokens, or add a `count` typography role.
- **low** `rounded.word-pill-tablet` is defined, but no component references it. `word-pill-*` uses only `{rounded.chip}`. Components prose also gives destructive buttons a "44 … in-alert" height, while `button-destructive.height` is 52 with no small variant. (DESIGN.md frontmatter; Components → Buttons, Inline alert). *Fix:* add `radiusTablet` to the word-pill components and `heightSmall: 44px` to `button-destructive`.

## 3. Component coverage — adequate
Checked: 30 DESIGN.md Components bullets against 29 EXPERIENCE.md Component Patterns rows, plus components named elsewhere (IA, Navigation model, State Patterns). Most pairs carry real rules on both sides.
### Findings
- **medium** The phone **Menu** is the only top-level navigation on iPhone, yet neither spine gives it a visual or behavioral spec (presentation, contents, focus, close). It survives only as `[ASSUMPTION]` and OQ-12. (EXPERIENCE.md IA → Navigation model; DESIGN.md Components → App header). *Fix:* add a Menu row to both spines (for example a bottom sheet listing the four areas with `aria-current`, closing on selection or scrim), even if marked `[ASSUMPTION]`.
- **medium** The unsaved-changes confirmation ("Discard unsaved changes?" Discard / Keep editing) is assigned to **Alert dialog**. That dialog's visual spec is delete-specific: trash icon disc in `danger-soft`, Destructive button first, Card chips. It is unclear whether "Discard" is destructive-styled or what icon appears. (EXPERIENCE.md Component Patterns → Alert dialog; DESIGN.md Components → Alert dialog). *Fix:* add an unsaved-warning variant to DESIGN.md that names its icon (or none), button order and button styles.
- **low** Component names drift between the files: "Queue-count chip" vs "Queue count", "Text field / textarea / select" vs "Text field", "Verification banners" vs "Verification banner". "Level meter" has a behavior row but no DESIGN.md Components bullet (it is described only inside Record button). "Progress card" has a DESIGN.md bullet but no behavior row (can the user leave during Apply?). (both spines, Components sections). *Fix:* align the names verbatim, add a Level meter bullet, and add a Progress card behavior row.
- **low** The "‹ Captures" back link and the "Use as is / Custom value" text-source choice have no component spec in either file. The choice is mentioned only through Text field's "active custom value" border. (EXPERIENCE.md Navigation model, Key strings; DESIGN.md Text field). *Fix:* name the control type (radio pair or segmented picker) and the back-link style.

## 4. State coverage — adequate
Checked each IA surface against the states that apply: empty, cold-load, busy, error, permission-denied and focus. Draft, Item detail, Review and Setup are well covered, and the copy for most states is quoted from `S-States` / `S-SetupStates`.
### Findings
- **high** **Pronunciation has no cold-load state.** PRD UJ-3 and FR-36 sync *before* the session and then show the first Card, which can take seconds. State Patterns has no "Loading — queue / syncing" row, and J3 step 1 jumps straight to the queue-count chip. The behavior when the pre-session Sync fails is also unstated (FR-36: non-blocking). (EXPERIENCE.md State Patterns; J3 step 1). *Fix:* add a row covering the skeleton and label while syncing and loading the queue, with Sync failure proceeding silently to the queue (terminal-only), and add the step to J3.
- **medium** Items (per Language) lacks a loading state and an empty state for when the Language has no Items yet. Only "Search no matches" is covered, and the "Loading" row lists Item detail, Captures and Setup but not Items. (EXPERIENCE.md State Patterns). *Fix:* add both rows with copy, for example "No English Items yet. Items are made from Captures."
- **medium** Setup's "nothing to change" state is referenced by J5 step 7 ("A later re-run shows no changes") but not specified. When the change list is empty, it is unclear whether Apply is disabled, hidden, or shown with a message. (EXPERIENCE.md State Patterns; J5 step 7). *Fix:* add a row with copy and the Apply button's state.
- **low** These smaller gaps remain: Voice catalog fetch failure (FR-26), an OpenRouter outage as distinct from a validation failure (PRD §5.2), and when "Generate draft" is disabled (Custom value selected but empty). "Assessing" is unmocked, and its rule "Rating stays available only if a prior Attempt exists" should be confirmed against the Rating row. (EXPERIENCE.md State Patterns; Component Patterns). *Fix:* add one row each, or fold them into existing rows.

## 5. Visual reference coverage — strong
Checked: `mockups/` holds 14 files, and every one is cited by name in both spines at the relevant IA row or component bullet, with what it illustrates. `wireframes/` does not exist and `imports/` is empty. The spines-win-on-conflict rule is stated once (EXPERIENCE.md Foundation) and DESIGN.md points to it. No orphans.
### Findings
- **low** The Key strings table is headed "from mockups", but some strings differ from the mockups. `S-Items` shows the search placeholder "Search English Items", while the spine has "Search English or Russian". `S-Review` labels the sub-score "Complete", while the spine has "Complete(ness)" and Pronunciation Feedback has "Completeness". (EXPERIENCE.md Voice and Tone → Key strings; Pronunciation Feedback). *Fix:* commit one string per slot and drop "(ness)". Spines win, so mark the spine value canonical.

## 6. Bloat & overspecification — strong
Little bloat. Tables are used where they fit, the source restatement in Foundation and IA is limited to FR anchors, and the invented Pronunciation Feedback section is load-bearing.
### Findings
- **low** DESIGN.md Components prose restates frontmatter values that the token reference already carries, for example "`border` (`#E2DACF`) fill, `ink-muted` text (5.1:1)" in Disabled button and pixel radii and sizes in Success banner and Queue-count chip. The Pronunciation Feedback table's "Queue count" and "Mockup" rows repeat IA and Component Patterns. (DESIGN.md Components; EXPERIENCE.md Pronunciation Feedback). *Fix:* keep the token references and drop the restated literals.

## 7. Inheritance discipline — adequate
Checked: all `sources` paths resolve (`../prd-languagelab/prd-languagelab.md`, `../prd-languagelab/addendum.md`, `../../../spec-draft.md`) and `design: DESIGN.md` resolves. FR and UJ IDs match the PRD. Glossary terms are used capitalized and consistently. EXPERIENCE.md token references resolve. Compared against `.memlog.md`: no contradictions. Queue-chip format and placement, duplicate-sheet button order, delete dialog, tap/tap recording, per-action errors, the non-colour cues, the 14-file mockup set and light-only all match.
### Findings
- **medium** The en-US phoneme pills in `S-Review` render IPA symbols ("k ə n k l u ʒ ə n z"). The addendum and spec-draft say "No Speechace, SPPAS, custom phonemizer or IPA overlay in v1", and the PRD non-goals list "No IPA". Neither spine says which phoneme alphabet the pills show (Azure returns IPA or SAPI) or why this does not count as an IPA overlay. (DESIGN.md Weak-word panel; EXPERIENCE.md Weak-word panel / Pronunciation Feedback). *Fix:* commit the alphabet and record the reasoning, for example "Azure's own phoneme labels, as returned, are not an IPA overlay", or switch to a non-IPA rendering.
- **medium** The memlog decision "Capture detail does not show Items created from it" is absent from both spines. A builder adding a "made from this capture" list would not be stopped. (EXPERIENCE.md IA → Capture detail; Component Patterns). *Fix:* state it in the IA row or the Success banner rule.
- **low** The Key Flow titles are memlog names ("Capture mid-task", "Batch processing at the Mac"), not the PRD UJ titles verbatim. The IDs are cited. The glossary list omits the PRD terms "Anki" and "Study Cards". OQ-16 says Capture delete has "no Cards", but FR-13 deletes the Capture's (suspended) card. (EXPERIENCE.md Key Flows headings; Voice and Tone → Glossary; Open Questions OQ-16). *Fix:* append the PRD UJ title in each heading, complete the glossary list, and reword OQ-16 to say no Exercise Cards are affected.

## 8. Shape fit — strong
DESIGN.md sections are in canonical order (Brand & Style → Colors → Typography → Layout & Spacing → Elevation & Depth → Shapes → Components → Do's and Don'ts). EXPERIENCE.md has all the required defaults. Responsive & Platform is present, as triggered by three first-class surfaces, and Inspiration & Anti-patterns is present, as triggered by the rejected directions A and B and the anti-gamification stance. Pronunciation Feedback and Open Questions are invented sections that earn their place.
### Findings
- **low** DESIGN.md "Open design questions" (DQ-1…4) is nested as an H3 under Do's and Don'ts, so a parser of hard visual rules picks up open questions. (DESIGN.md end). *Fix:* move it to a separate trailing H2 after Do's and Don'ts.

## Mechanical notes
- Frontmatter: both spines carry title, status, created, updated and sources. DESIGN.md also carries `name` and `description` per spec. The YAML is well-formed by inspection (memlog records a successful parse; pyyaml was unavailable for a re-check).
- Cross-refs: all `{colors|typography|rounded|spacing|components.*}` references resolve. The shorthand "`{typography.score-headline}` / `-tablet`" in the DESIGN.md Typography table is not a resolvable path. Write `{typography.score-headline-tablet}`.
- Unused tokens: `rounded.word-pill-tablet`. `colors.danger-outline` and `colors.accent-hover` are named in prose only, without the `{}` syntax. That is acceptable but inconsistent.
- Name inconsistencies: Queue-count chip / Queue count; Text field / textarea / select / Text field; Verification banners / banner; Complete / Completeness.
- No Mermaid diagrams are present.
- Open-question IDs: DESIGN.md DQ-1…4 and EXPERIENCE.md OQ-1…16 cross-reference correctly (DQ-1↔OQ-11, DQ-3↔OQ-6, DQ-4↔OQ-5).
