# Issue tracker: Linear

Issues and specs for this repo belong in a Linear project named `Language Learner`. Create it in the workspace's default team and set the repo owner as project lead. Record its URL here once created. Until then, the project is **pending creation**.

Use the connected Linear MCP server to read, create, and update issues. The Linear desktop client is the owner's interface. If Linear tools are unavailable in a session, ask the owner for the relevant issue text and prepare the exact title, description, labels, relationships, or comment for them to apply in the desktop client. Do not treat a proposed issue as published until its Linear identifier or URL is returned.

## Conventions

- Create specs and implementation tickets in the `Language Learner` project.
- Use Linear issue identifiers and URLs when referring to existing work.
- Read the issue description, comments, status, labels, assignee, and relationships before acting on a ticket.
- Use Linear's blocking relationships for dependencies. For a ticket plan, create the issues first, then link blockers once identifiers exist.
- For triage, map canonical roles to Linear labels using `docs/agents/triage-labels.md`.

## Skill requests

- **Publish to the issue tracker:** Create a Linear issue in this project and return its identifier and URL.
- **Fetch the relevant ticket:** Read the Linear issue and its current properties and comments.
- **Claim a ticket:** Assign the Linear issue to the working owner or agent before starting work.
- **Resolve a ticket:** Post the result to the Linear issue and update its status.
