# Domain docs

This repo uses a single-context layout: `CONTEXT.md` at the repo root and ADRs in `docs/adr/`.

Before exploring the codebase, read `CONTEXT.md` and any ADRs that touch the area of work. If these files do not exist yet, proceed. The `/domain-modeling` skill creates them when terms or decisions are resolved.

Use the glossary's terms in issue titles, proposals, hypotheses, and tests. If a needed term is absent, reconsider it or note the gap for `/domain-modeling`.

If work contradicts an existing ADR, identify the ADR and surface the conflict explicitly.
